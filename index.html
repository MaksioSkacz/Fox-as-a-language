THE FOX LANGUAGE

Write Fox.
Compile native.

Fox is a small programming language with a Python-written compiler that emits Windows x86-64 machine code into a native PE32+ executable. These docs describe the implemented language—not a wish-list of future features.

01 / GET STARTED

Your first Fox program

⌘

Create a file named hello.fox. Include Con to print text or values, then call Console.log.

FOX hello.fox
include Con as Console

Console.log("Hello from Fox!")
Console.log(2 + 3)

From PowerShell, use the fox command configured on your machine. The commands below assume it is available on PATH or defined in your PowerShell profile.

Compile and runfox hello.foxfox hello.fox
Compile onlyfox hello.fox --compile-onlyfox hello.fox --compile-only
Choose output pathfox hello.fox -o build\hello.exefox hello.fox -o build\hello.exe

Remember

With --compile-only, the compiler writes a sibling .exe unless -o is specified. Without --compile-only, the compiler launches the newly built executable.

02 / TOOLCHAIN

Compiler & commands

⚙

The compiler is implemented in Python. It parses the supported Fox subset, emits machine code and builds a Windows PE32+ executable directly; it does not invoke an assembler or linker as part of the normal compile path.

CommandBehavior
fox file.foxCompile to a temporary executable, then run it.
fox file.fox --compile-onlyWrite file.exe and stop after compilation.
fox file.fox -o out.exeWrite to out.exe and, unless compile-only is also provided, launch it.
fox --helpShow the command-line help exposed by the compiler.
!
Platform target

The emitted binary targets Windows x86-64. A generated EXE is not a cross-platform executable and will not run natively on Linux or macOS.

03 / LANGUAGE GUIDE

Syntax & comments

{ }

Fox is line-oriented. Most statements occupy a single line, and blocks close with the exact marker end:. Indentation improves readability, but block boundaries are determined by the keywords and closing marker.

Comments

A # begins a comment outside a quoted string. The compiler ignores text from the marker to the end of that line.

comments.fox
# This is a whole-line comment
include Con as Console  # and this is trailing
Console.log("The # inside this string is text")

Names & literals

Identifiers begin with an ASCII letter or underscore, followed by letters, digits, or underscores. String literals use double quotes and JSON-style escapes, such as \n, \t, \", and \\.

Numbers

42, -8, 3.14, 1e3

Boolean literals

true and false

Null literal

null

Block terminator

end: closes blocks

Reserved words include include, variable, constant, true, false, null, while, if, else, for, to, step, end, and return. Some forms, such as include, are restricted to top-level code.

04 / DATA MODEL

Values & types

◈

Fox distinguishes mutable scalar state emitted into the executable from values resolved while compiling. Native runtime scalars include signed integers, IEEE-754 binary64 floats, booleans and explicitly typed strings. Array and dictionary literals remain compile-time data; RuntimeArray supplies a separate mutable numeric buffer API.

01Runtime

Scalar state

Integer and float arithmetic, boolean flags, typed string slots, function arguments/locals, comparisons and loop state compile to native code.

variable speed: float = 2.5
02Compile-time

Static values

Unannotated string values, constants, nested arrays and dictionaries can be resolved while compiling. Add : string to declare a runtime string slot.

constant title = "Fox"
Type / valueExampleCurrent behavior
Integer17Runtime signed integer; integer division truncates toward zero.
Float / number2.5Runtime binary64 value. Annotate as : float (or : number) when you need to pin the type.
BooleantrueBoolean variables can hold runtime state; comparisons produce booleans. ==/!= can compare two booleans at runtime.
Stringvariable label: string = "hello"Typed runtime strings can be assigned, passed to typed functions, returned and logged. Unannotated literal strings may remain compile-time values.
NullnullCompile-time literal; not a general runtime nullable-reference type.
Array[1, 2, 3]Compile-time sequence with zero-based integer indexes; no runtime mutation or dynamic indexing.
Dictionary / table{"name": "Fox", 2: "level"}Compile-time key/value data. Keys may be strings or integers; lookup uses a compile-time key.
!
Literal collections are not runtime containers

A normal array or dictionary is evaluated during compilation. Use RuntimeArray or World3D for native heap-backed numeric data that changes while the program is running. See the memory helper reference.

05 / DATA MODEL

Variables & constants

x =

Declare values

variables.fox
include Con as Console

constant app_name = "Fox Tools"
variable score = 0
variable decimal_value = 3.5
variable enabled = true

score += 10
score *= 2
Console.log(score)

constant marks a compile-time value as non-reassignable. Unannotated scalar variables initialized with numbers or booleans are runtime state; explicit annotations such as variable speed: float = 3.5 and variable title: string = "Fox" select a runtime type. Unannotated string/array/table literals may remain compile-time values.

Assignment operators

=+=-=*=/=%=^=

Inside blocks, assign to declared runtime state. Numeric variables support matching numeric assignments (inferred numeric variables can promote from integer to float); boolean variables accept booleans, and typed strings accept strings. Declarations inside top-level if/while/for blocks are not supported; declare mutable state before the block.

06 / EXPRESSIONS

Operators & expressions

∑
OperatorPurposeNotes
+Addition / string concatenationRuntime numbers support addition; two compile-time strings can be concatenated with +. Runtime string concatenation is not supported.
-Subtraction / unary negativeRuntime integer and float arithmetic.
*, /, %Multiply, divide, remainderRuntime integer and float arithmetic. Integer division truncates toward zero; float remainder uses floating-point remainder semantics.
^ExponentiationSupported at compile time and at runtime for numeric operands. Power is right-associative: a ^ b ^ c means a ^ (b ^ c).
==, !=Equality / inequalityNumeric values are comparable; runtime boolean equality/inequality is supported. Runtime string comparisons are not.
<, >, <=, >=Numeric comparisonAccept runtime integer or float operands.
( )GroupingUse parentheses to control evaluation order.

Precedence

Parentheses bind first; exponentiation binds more tightly than unary minus; then multiplication/division/remainder; then addition/subtraction; then one comparison. For example, -2 ^ 2 means -(2 ^ 2).

expressions.fox
include Con as Console

variable result = (4 + 6) * 2
variable power: float = 2.0 ^ 3.0
Console.log(result)
Console.log(power)

if power >= 8.0
    Console.log("ready")
end:

Chained comparisons such as a < b < c are rejected. Logical operators such as &&, and, or, and boolean negation are not implemented; use nested if statements instead.

07 / CONTROL FLOW

Control flow

↳

if / else

Conditions must evaluate to a boolean: either a compile-time true/false or a comparison. The optional else branch shares the same closing end: marker.

if.fox
include Con as Console
variable power = 15
if power > 0
    Console.log("Power online")
else
    Console.log("Power depleted")
end:

while

Repeats while the condition is true. Runtime loops can use integer comparisons and update previously declared integer state.

while.fox
include Con as Console
variable count = 0
while count < 3
    Console.log(count)
    count += 1
end:

for

Fox's range loop uses for name = start to limit with an optional constant integer step. The limit is exclusive: the loop continues while the counter is less than the limit for positive steps, or greater than the limit for negative steps.

for.fox
include Con as Console
for i = 0 to 5
    Console.log(i)  # 0, 1, 2, 3, 4
end:

for n = 6 to 0 step -2
    Console.log(n)  # 6, 4, 2
end:
!
Declare carefully

Runtime declarations inside top-level control-flow blocks are not supported. Declare mutable state before the block. Function-local integer declarations are supported inside functions.

08 / REUSE

Functions

f( )

Define a function with variable name(parameters) and close it with end:. Functions accept up to 16 parameters. Parameter/return annotations support integer, float (or number) and string; unannotated numeric return types are inferred. Function-local variables support scalar integer, float, boolean and string values.

functions.fox
include Con as Console

variable multiply(a: float, b: float): float
    return a * b
end:

variable greeting(name: string): string
    return "Hello, " + name
end:

variable answer = multiply(4.0, 2.5)
Console.log(answer)
Console.log(greeting("Fox"))

Function rules

  • ✓Unannotated parameters default to integer; parameters can be explicitly typed as integer, float/number or string. A string argument can infer an unannotated string parameter.
  • ✓Scalar return types can be integer, float, string or boolean; return annotations currently allow integer, float/number or string.
  • ✓Function-local declarations support runtime scalar values, but local constant declarations are not supported.
  • ✓Functions can be called in expressions or as statements. A function that reaches its end without an explicit return defaults to 0.
  • !GUI button, paint and timer callbacks plus thread entry functions must have zero parameters.

A return annotation follows the parameter list: variable scale(x: float): float. User function arguments and return values are passed through the native x64 calling convention in the generated executable.

09 / DATA

Arrays & dictionaries

[ ]

Arrays and dictionaries are compile-time data structures: the compiler evaluates literals and resolves lookups while compiling. Arrays use zero-based integer indices. Dictionaries (tables) accept unique string or integer keys. Neither is a heap-allocated mutable runtime collection.

collections.fox
include Con as Console

variable items = ["first", "second", "third"]
variable player = {
    "name": "Fox",
    "level": 3,
    "online": true
}

Console.log(items[0])
Console.log(player["name"])
Console.log(items)
Array indexes

Zero-based integer indexes, for example items[0]. Out-of-range access is a compile error.

Dictionary keys

Keys can be unique quoted strings or integer literals. Read with player["name"] or table[2].

Nested arrays and dictionaries are supported as literals, including lookups by integer table key. Static values can be logged directly with Console.log. Dynamic indexing and runtime mutation are not implemented; use the RuntimeArray helper for runtime numeric storage.

10 / PROJECT STRUCTURE

Modules & includes

⇢

include statements must appear at the top level. The compiler has native Con, Win, Thread and Mouse APIs. Source modules—including GPU, Vulkan, Keyboard, Math, Renderer, Plot and World3D—are expanded from matching files in helpers/. The complete API reference lists the graphics backends and helper families.

includes.fox
include Con as Console
include Win as Win
include Thread as Thread
include Mouse as Mouse

Custom source modules

For a non-built-in include, the compiler looks for a sibling file named after the module, such as MathTools.fox for include MathTools as Tools. That file's source is inlined before parsing, and nested module includes are expanded recursively.

Project layout
project/
├── main.fox
└── MathTools.fox

Custom include aliases are not namespaces. Define a function such as sum_to(n) in MathTools.fox and call it as sum_to(5), not Tools.sum_to(5). Cyclic includes are rejected.

11 / BUILT-IN MODULES

Con — console

›_

Include the module with any legal alias. The examples use Console.

Console.log()output

Writes a newline. Accepts zero or one argument. A compile-time value can be a string, number, boolean, null, array or dictionary; a runtime expression must be an integer expression.

Console.log("Hello")Console.log(7 * 6)

There are no implemented Console.clear, formatted-string interpolation, or input-reading methods in the current compiler. Unsupported methods are compile errors.

12 / BUILT-IN MODULES

Win — windows & GUI

▣

The Win module creates native Windows GUI windows and basic controls, plus GDI drawing and framebuffer presentation. The timer paint path suppresses background erasure to prevent white flashes between frames.

Win.message_box(title, message)dialog

Shows a Windows message box. Both parameters must be compile-time strings.

Win.window(title, width, height)window

Creates a window and immediately enters its message loop. Use it for a simple blank window; code after this call won't run until that window closes.

Win.begin(title, width, height)window

Creates a window but does not enter the message loop yet. Use this form when controls or paint callbacks need to be registered. Only one Win.begin window is currently supported.

Win.maximize()window

Maximizes the window created by Win.begin.

Win.set_resizable(true_or_false)window

Enables or disables resizing. Pass a boolean literal, such as false.

Win.label(text, x, y, width, height)control

Adds a native static-text control after Win.begin.

Win.button(text, x, y, width, height, "callback")control

Adds a native button. The callback name is a quoted string that refers to a defined Fox function with zero parameters.

Win.rect(x, y, width, height, color)drawing

Draws a filled rectangle. Coordinates and dimensions are integer literals; dimensions must be positive. Color is a Windows COLORREF value from 0 through 16777215.

Win.text(text, x, y, color)drawing

Draws a text string at a position using the given COLORREF. Coordinates and color must be integer literals.

Win.paint("callback")drawing

Registers one zero-parameter function to call on a paint message. Register after Win.begin; drawing calls in this function redraw the scene when Windows repaints.

Win.run()event loop

Starts the message loop for the window created by Win.begin. It must be called once after creating the window.

Minimal custom-drawn window

gui.fox
include Win as Win

Win.begin("Fox Window", 800, 600)

variable draw_scene()
    Win.rect(0, 0, 800, 600, 2236962)
    Win.text("WELCOME TO FOX", 30, 30, 16777215)
end:

variable clicked()
    Win.message_box("Fox", "Button clicked!")
end:

Win.button("Click me", 30, 80, 140, 40, "clicked")
Win.paint("draw_scene")
Win.run()

Drawing calls are compiler-known GUI operations with literal arguments, not a general-purpose graphics API. There is no image/sprite loader, audio API, keyboard/mouse event API or animation timer in this version.

13 / BUILT-IN MODULES

Mouse — cursor & relative input

⌖

The built-in Mouse module is designed for games and custom-drawn windows. Capture clips the cursor to the client area, and relative movement deltas support first-person camera controls.

Mouse.capture(true_or_false)capture

Captures/clips the cursor to the Fox window or releases it. Focus changes release or restore capture.

Mouse.hide() / Mouse.show()cursor

Hides or restores the Windows cursor.

Mouse.update()input

Updates position and frame-to-frame deltas. Call before reading movement for each update tick.

Mouse.x() / Mouse.y()position

Reads the latest cursor position relative to the client area.

Mouse.delta_x() / Mouse.delta_y()relative

Reads horizontal and vertical movement since the previous Mouse.update().

mouse_camera.fox
include Win as Win
include Mouse as Mouse

Win.begin("Fox Camera", 1280, 720)
Win.maximize()
Win.set_resizable(false)
variable update()
    Mouse.update()
    variable dx = Mouse.delta_x()
    variable dy = Mouse.delta_y()
end:
Mouse.capture(true)
Mouse.hide()
Win.timer("update", 16)
Win.run()

Use capture during gameplay and release it when returning to menus. Keep an exit path such as Alt+F4 while developing.

14 / SOURCE HELPER LIBRARY

Renderer, Plot & OS helpers

▦

These modules live in the project's helpers/ directory and are expanded into the same native executable as the calling Fox source.

Renderer.create(width, height)framebuffer

Creates a pixel buffer which can be drawn to and presented using Win.pixels(frame, width, height).

Renderer.clear / pixel / rect / linedrawing

Clears the buffer and draws pixels, filled or outlined rectangles, and line segments.

Renderer.triangle / circle / fill_circle / cubegeometry

Raster primitives for interfaces, plots, and simple software-rendered scenes.

Plot.grid / Plot.sine / Plot.cosineplotting

Draws coordinate grids and mathematical curves into a renderer buffer.

OS.mkdir / exists / copy / move / deletefilesystem

Provides basic directory and file operations. Status values use integer success/failure results.

OS.save_text / append_text / read_textfiles

Creates, appends and reads UTF-8 text files.

renderer.fox
include Win as Win
include Renderer as Renderer
include Color as Color
constant W = 960
constant H = 640
variable frame = Renderer.create(W, H)
Win.begin("Fox Renderer", W, H)
variable draw_scene()
    Renderer.clear(frame, W, H, Color.dib_rgb(12, 16, 30))
    Renderer.circle(frame, W, H, 480, 320, 100, Color.dib_rgb(255, 80, 180))
    Win.pixels(frame, W, H)
end:
Win.paint("draw_scene")
Win.run()

15 / BUILT-IN MODULES

Thread — concurrency

⇄

Thread.start launches a zero-parameter Fox function on a Windows thread. Thread.wait waits for started worker threads to finish.

threads.fox
include Con as Console
include Thread as Thread

variable worker()
    Console.log("Worker started")
end:

Thread.start("worker")
Thread.wait()
!
Keep shared state simple

The current runtime does not provide mutexes, locks, channels or an atomic-variable API. Concurrent access to shared mutable state can race. Worker functions must have zero parameters.

17 / LANGUAGE STATUS

Current limitations

◷

Fox is an evolving compiler, so some features that look familiar from other languages are not yet implemented. These are current implementation constraints, not recommended language design.

01
Runtime features are typed and bounded

The current compiler supports native numeric values, typed string operations and runtime arrays. Some literal arrays and dictionaries are still resolved at compile time.

02
No logical operators

There is no and/or/not or &&/|| expression support. Chained comparisons are rejected.

03
No runtime declaration in top-level blocks

Declare globals before top-level runtime if, while or for blocks.

04
Native GUI and software graphics

Fox supports Win32 windows, timers, keyboard polling, mouse capture, a CPU software framebuffer, and native OpenGL 1.1 fixed-function rendering through GPU. The experimental Vulkan backend currently clears and presents swapchain images only; it is not a mesh renderer. There is no built-in audio system.

05
Limited thread coordination

Threads can be started and joined, but there are no built-in locks, message queues or safe shared-state primitives.

06
One window and paint callback

The current compiler accepts one Win.begin window and one Win.paint callback per program.
