01 / GRAPHICS BACKENDS

GPU — native OpenGL 1.1

◇

GPU wraps Windows WGL and the system opengl32.dll. Once a context is created, OpenGL's installed driver handles geometry rasterization; this is distinct from the CPU framebuffer exposed by Renderer. Call Win.begin first, then GPU.start().

GPU.start() / GPU.shutdown() / GPU.present()context

Creates/releases the OpenGL context and presents the rendered frame. GPU.start() returns 1 on success.

GPU.begin_frame(r, g, b, a, width, height)frame

Sets the viewport, clears color and depth buffers, and resets the model-view matrix. RGBA components are floats from 0 to 1; projection/camera matrices remain your responsibility.

GPU.clear_color(r, g, b, a) / clear(mask) / viewport(x, y, w, h)frame state

Sets the clear color, clears selected buffers, and sets the viewport. Common flags include GPU_GL_COLOR_BUFFER_BIT and GPU_GL_DEPTH_BUFFER_BIT.

GPU.matrix_mode / load_identity / frustum / ortho / translate / rotatetransforms

Controls OpenGL's fixed-function projection and model-view matrices. The caller chooses projection, camera and object transforms.

GPU.begin(mode) / color / texcoord / normal / vertex / end()geometry

Submits immediate-mode primitives such as GPU_GL_TRIANGLES, GPU_GL_QUADS, points, strips and fans.

GPU.enable / disable / cull_face / polygon_moderender state

Toggles depth testing/culling and chooses cull face and polygon fill/line mode. Constants such as GPU_GL_DEPTH_TEST, GPU_GL_BACK and GPU_GL_LINE come from helpers/GPU.fox.

GPU.gen_lists / new_list / end_list / call_list / delete_listsdisplay lists

Stores static immediate-mode geometry in driver-managed OpenGL display lists, replays it later, or releases the list IDs.

GPU.texture_new(width, height, rgba_pointer) / texture_bind / texture_deletetextures

Uploads RGBA8 pixels from a native pointer, binds a texture, or deletes it. The source buffer must contain at least width × height × 4 bytes and remain valid until upload returns. Pass RGBA byte order, not the DIB packed-color value.

GPU.vendor / renderer / version / extensions / get_integer / get_errordriver query

Queries driver strings, one integer capability, or the OpenGL error code. Examples include GPU_GL_MAX_TEXTURE_SIZE and GPU_GL_MAX_LIGHTS. Do not use get_integer for multi-value queries such as the viewport.

Minimal triangle

gpu_triangle.fox
include Win as Win
include GPU as GPU

Win.begin("Fox OpenGL", 800, 600)
variable gpu_ready = GPU.start()
if gpu_ready == 1
    GPU.enable(GPU_GL_DEPTH_TEST)
    GPU.matrix_mode(GPU_GL_PROJECTION)
    GPU.load_identity()
    GPU.ortho(-1.0, 1.0, -1.0, 1.0, -10.0, 10.0)
end:

variable draw_frame()
    if gpu_ready == 1
        GPU.begin_frame(0.025, 0.035, 0.07, 1.0, 800, 600)
        GPU.begin(GPU_GL_TRIANGLES)
        GPU.color(1.0, 0.2, 0.15, 1.0)
        GPU.vertex(-0.6, -0.5, 0.0)
        GPU.vertex(0.6, -0.5, 0.0)
        GPU.vertex(0.0, 0.6, 0.0)
        GPU.end()
        GPU.present()
    end:
end:

Win.paint("draw_frame")
Win.run()
if gpu_ready == 1
    GPU.shutdown()
end:
!
OpenGL 1.1 scope

This is the Windows compatibility/fixed-function API, not a modern shader pipeline. Fox does not currently expose programmable shaders, compute shaders, vertex/index-buffer objects, or standardized VRAM/temperature/power sensors. Driver acceleration depends on the installed system; GPU.renderer() may report a software fallback such as GDI Generic.

The archive includes examples/gpu_cube.fox, driver diagnostics, and texture upload smoke tests. Compile checks do not prove the code displays correctly; test context creation on a real Windows desktop with a compatible driver.

02 / GRAPHICS BACKENDS

Vulkan — probe & clear renderer

▧

The Vulkan helper dynamically loads vulkan-1.dll, so it is not a mandatory import for every Fox program. Its device probe reports information about the first enumerated physical device. A separate experimental Win32 renderer creates a surface and swapchain, then clears and presents swapchain images.

Vulkan.start() / Vulkan.shutdown()probe

Initializes/releases the loader and instance for device inspection. Check the integer result before querying details.

Vulkan.device_count() / device_name()device

Reports enumerated devices and the selected first device's name.

Vulkan.api_version / driver_version / vendor_id / device_id / device_type / last_resultdevice info

Returns packed API/driver versions, vendor/device IDs, a device-type code (1 integrated, 2 discrete, 3 virtual, 4 CPU, 0 other), and the latest loader/Vulkan status.

Vulkan.render_start() / render_frame(r, g, b, a) / render_shutdown()clear renderer

Call Win.begin first. render_start creates a Win32 surface, device, compatible graphics/present queue and swapchain. render_frame clears one image to RGBA float channels from 0 to 1 and presents it. Release resources with render_shutdown.

Vulkan.render_diagnostic()diagnostics

Displays a popup with the last Vulkan result or custom initialization stage code.

vulkan_clear.fox
include Win as Win
include Vulkan as Vulkan

Win.begin("Fox Vulkan clear test", 960, 640)
Win.set_resizable(false)
variable ready = Vulkan.render_start()

variable redraw()
    if ready == 1
        Vulkan.render_frame(0.10, 0.10, 0.30, 1.0)
    end:
end:

if ready == 1
    Win.paint("redraw")
    Win.timer("redraw", 16)
    Win.run()
else
    Vulkan.render_diagnostic()
end:
Vulkan.render_shutdown()
!
Not a mesh renderer yet

The current Vulkan code is clear-and-present only. It has no shader/SPIR-V support, graphics pipeline, vertex/index buffers, depth buffer, texture sampling, materials, lighting, or swapchain recreation on resize. It waits for the queue on each frame, so this is a diagnostic foundation, not a performance renderer. FoxCraft3D uses OpenGL instead.

03 / SOURCE HELPERS

Input, time & colors

⌁
Keyboardinput

Key constants: W/A/S/D, arrow keys, SPACE, ENTER, ESCAPE, SHIFT, CTRL, mouse buttons, KEY_1–KEY_4. Keyboard.is_down(vk) reads the Win32 held-key bit; Keyboard.pressed(vk) reads the “pressed since previous call” hint. Both return integer booleans. This is polling, not a buffered event API.

Time.seconds() / Time.elapsed_ms(start_ms)timing

Uses Windows GetTickCount. Its 32-bit millisecond counter wraps after about 49.7 days; use elapsed deltas for short timers.

Color.rgb / red / green / blue / gray / dib_rgbcolors

rgb returns a Win32 COLORREF for GDI drawing, with red in the low byte. dib_rgb returns packed 0x00RRGGBB for Win.pixels framebuffer data. These formats are different; choose the method for the target API.

Random.seed(value) / next() / range(minimum, maximum)random

Deterministic integer linear-congruential pseudo-random generator. range includes both endpoints; this is not cryptographically secure randomness.

05 / SOURCE HELPERS

3D data & native memory

▦
RuntimeArraynative buffers

create(count), length(buffer), get_int/get_float(buffer,index), set_int/set_float(buffer,index,value), free(buffer). Uses zero-based indices and native 64-bit slots. Pair setters/getters by type, check setter success (1 or 0), and free allocated buffers when done.

World3Dvoxel storage

in_bounds, index, create, get, set, place, remove, free, chunk_coord, local_coord, cell_center. Creates a flat, mutable world of integer block IDs; 0 means air. You own the buffer lifetime and must call free.

!
Runtime memory vs. literal collections

Fox array and dictionary literals are currently compiler-time values. Use RuntimeArray or World3D for numeric storage that changes while a compiled program runs. Returned buffer handles are opaque integer pointers, not ordinary arrays.

06 / SOURCE HELPERS

Rendering, plotting & files

▤
RendererCPU framebuffer

create/destroy, pixel, clear, rect, rect_outline, line, triangle, circle, fill_circle, vertex_x/y/z, project_x/y, and cube. Draws in software to a native pixel buffer; present it with Win.pixels(buffer,width,height). The projected cube functions are simple sample geometry, not a general 3D scene graph.

Plotfunctions & curves

map_x/map_y, grid, sine, cosine, quadratic, samples. Curves and point samples are rasterized into a Renderer buffer using plot bounds, sample counts and packed colors. The custom-samples helper reads numeric values from supplied runtime buffers.

OSfilesystem

mkdir/create_dir, exists, delete/remove, copy, move, save_text/write_text, append_text, read_text. Mutating/status functions return integer success/failure values; read_text returns a string. File data is UTF-8; Windows paths use the active ANSI code page.

Tkinter.center_x / center_y / row_y / column_xlayout helpers

Calculates coordinates for arranging native Win.label and Win.button controls. Despite the module name, this does not create Python Tkinter widgets or embed Python GUI code.

The helpers are intentionally small source-level building blocks. The package also contains game/rendering examples including a software-rendered cube, a plotter, a GPU OpenGL cube, a Vulkan clear demo, and the FoxCraft3D voxel sandbox.

!
Buffer and rendering contracts

Free every RuntimeArray, World3D or Renderer buffer when finished. OpenGL texture uploads consume contiguous RGBA8 memory. Color.rgb is a Win32 COLORREF, while Color.dib_rgb is the packed DIB framebuffer value; do not interchange them. OpenGL 1.1 is fixed-function, and Vulkan is clear/present only.

07 / STATUS

Implementation limits

◷

Compilation to PE32+ and successful imports are not proof of display correctness. OpenGL context creation and Vulkan surface/swapchain presentation should be tested on an actual Windows desktop and supported driver.

01
OpenGL

Fixed-function OpenGL 1.1 only; no programmable shaders or compute, and no standardized hardware sensor API.

02
Vulkan

Clear and present only. No mesh pipeline, shader compilation, depth/texture/material system, or swapchain resize recovery yet.

03
Windows GUI

One Win.begin window, one paint callback and one timer callback per program. The timer-driven rendering API is Windows-specific.

04
Concurrency

No built-in locks, atomics, channels or safe shared-state primitives. Shared mutable state can race across worker threads.
